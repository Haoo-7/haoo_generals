# 漠阗

称号：魏倚至何；体力/上限：4/4；男；铁势力；内部名 `mt__motian`，不显示角标。原画采用用户提供的《新UI.ACHA022.神也人也.漠阗原画.png》，原图1024×1024，裁切区域(64, 0, 940, 1024)，缩放为250×292的RGB JPEG，路径 `image/generals/mt__motian.jpg`。保留脸部、冠饰和持扇动作。未提供语音。

## 技能原文

- 后辅：游戏开始时，你选择一名后辅角色，其获得【天妒】。你回复若干体力或其受到若干伤害后，对方如是。
- 天嫉：你为【天妒】增加以下效果：未满足漠阗的胜利条件时你不能胜利；漠阗的准备阶段，你可以失去所有体力和【天妒】。
- 筹拔：你造成或受到伤害后可令本回合未判定过的角色判定，若判定花色已记录，你对其造成一点伤害，否则你记录并摸其已记录花色张牌。

## 已逐项确认的规则

- 后辅只能选择一名其他存活角色，不可取消。有合法目标时必选。其获得原版天妒，原本已有天妒时不叠加。
- 漠阗实际回复X点体力后，后辅回复X点；后辅受到X点伤害后，漠阗受到X点无来源普通伤害。双方各自仍适用回复上限、伤害增减、防止、护甲与濒死流程。相反方向不联动。
- 后辅关系不依赖对方仍有天妒；漠阗失去后辅或技能失效时，不发动这项联动。关系记录保留至本局结束，死亡本身不删除关系；死者不会被回复或承担联动伤害。
- 天嫉影响全场所有拥有天妒的角色，包括原本的郭嘉及后来获得天妒的角色。
- 模式先按原规则计算正常胜者；当漠阗不在正常胜者中时，仍有效持有天妒的角色不得获胜。漠阗满足胜利条件时，天妒持有者仍需满足自己的胜利条件，不会自动加入胜者。已死亡但符合模式团队胜利条件的角色仍参与判断。
- 多名漠阗分别施加天嫉限制，按未经删改的正常胜者名单检查每人条件。任一天嫉拥有者不满足胜利条件时，天妒持有者不能胜利。失去或无效天嫉时不再提供这份限制。若所有正常胜者都被排除，沿用引擎空胜者名单的平局显示。
- 每名有效天妒持有者在漠阗准备阶段各自决定是否解除。选择后，先失去天妒（包括原生与借用来源），再失去此刻全部正体力至0，按正常规则进入濒死求救。获救后仍无天妒。失去体力不作为伤害，不触发筹拔。
- 筹拔每次造成伤害后与受到伤害后分别提供一次可选机会，不按伤害点数重复。自伤同时产生两个时机。可以选择本回合未判定过的自己。
- 2026-11-20修订：目标须为本回合未判定过的存活角色。通过原生判定事件历史检查，任意技能、判定区牌、装备等产生的判定都计入，已经开始但尚未结束的判定也计入；无需此前拥有筹拔。所有漠阗共用该限制。选择和效果执行前均检查目标，所有角色都已判定时不询问。限制按每名角色的完整回合计算，跨阶段不重置，下一回合（包括额外回合）恢复可选。
- 花色按每名被判定角色分别记录，记录持续至本局结束；不随回合、轮次、技能丢失或死亡清空。多名漠阗共用该角色的筹拔花色记录。
- 未记录的新花色先加入记录，再按该角色当前花色数摸牌，依次可为1、2、3、4张。重复花色只造成1点由漠阗发起的普通伤害，不摸牌。该伤害仍可再次触发筹拔，也可触发后辅，但本回合已经判定过的目标不能再选。每次新的询问都可以取消。
- 使用最终改判结果的花色。原版天妒可正常获得判定牌，牌被获得不影响记录结果；无花色或未形成判定结果时不记录、不摸牌、不造成伤害。
- 2026-11-25修正：以本次判定对应的原生事件确认是否完成；在判定开始、改判或判定结束时中断，均不记录、不摸牌、不造成追加伤害，即使已填充结果也不继续。嵌套判定的成功或中断不代替本次判定状态。

## 验证与实现范围

### 天嫉胜负接口核对（2026-11-25）

已核对官方 FreeKill `v0.5.25` 发布标签（提交 `671b0ad698c36b703808d8b29f3483ce54b36631`），其接口支持当前玩家数组实现：

- [`Room:gameOver`](https://github.com/Qsgs-Fans/FreeKill/blob/671b0ad698c36b703808d8b29f3483ce54b36631/ltk/server/room.lua#L3657-L3673) 接受 `ServerPlayer[] | Player[] | string`，先将玩家数组或身份字符串转换为玩家 ID 字符串，再调用底层结算。
- [`ServerRoomBase:victoryResult`](https://github.com/Qsgs-Fans/FreeKill/blob/671b0ad698c36b703808d8b29f3483ce54b36631/lua/server/roombase.lua#L349-L398) 按玩家 ID 计算胜负，底层的 `split` 接收到的是上层转换后的字符串。
- [客户端 `GameOverModel`](https://github.com/Qsgs-Fans/FreeKill/blob/671b0ad698c36b703808d8b29f3483ce54b36631/LunarLtk/Models/Popups/GameOverModel.qml#L53-L56) 用 `winner.split("+").includes(myId)` 判断胜负，`myId` 为玩家 ID。因此同为忠臣的两人，可以分别因持有与未持有天妒获得不同结果；不能将过滤结果重新拼成身份字符串，否则会丢失个人胜负差异。

官方发布源码与本机 freekill-core `37510743e7ff2f3abdfb134a1cd8d3a40735d748` 各通过 7 个原生结算场景：同身份一胜一败、直接传玩家数组、全部过滤后平局、漠阗获胜时保留天妒队友、死亡角色过滤、失去天妒后恢复资格及原生平局。每项检查结束事件、战报、武将与玩家胜率、广播名单及结束状态；两份 QML 的原始 JavaScript 胜负函数也通过同身份差异和平局检查。

上述验证执行原始 Lua 结算方法及协程结束路径；C++ 网络与持久化、空历史查询和事件派发使用替身，QML 函数通过 Node 执行，未验证实际界面渲染或多人对局。尚未取得实际服务器的核心提交，若服务器使用旧版或修改过的核心，应另行对照源码。review 中“官方 0.5.25 不接受玩家数组”的问题未复现，天嫉保留现有实现。
